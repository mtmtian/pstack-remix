### Opening a PR

Invoked at the end of every other playbook. Read the applicable PR rules and repository template. A read-only task, or one the user keeps local, ends without a PR. Work from a git worktree off trunk, give concurrent writers separate worktrees or owned files, and never reset, clean, or move another person's or unrelated changes to tidy the tree. Rebase into small, landable commits that tell the story. Review the diff directly under the shared runtime contract for unnecessary abstractions, weakened checks, hidden failures, and unrelated changes before commit, and run `$no-comments` before review.

Write the title, body, and commit bodies in the language that the user's PR rules or the repository's rules require, and in English only when neither names one; an English template or example does not change that language. Write them with `$technical-writing` (every layer except Diátaxis; for English text, also apply the STE vocabulary rules: one word per action, keep articles, a plain verb over `-ing` where one works), then `$unslop`. Title: `type(scope): subject`, naming a real symbol when one carries the change. Body: a one-minute briefing under 40 lines with these `##` headings in order, in the body's language, dropping empty ones: `## Why`, `## What changed`, `## Scope`, `## Tradeoffs` (only rejected alternatives a reviewer would otherwise ask about), `## Blast Radius`, `## Verification`; in Simplified Chinese, `## 背景`, `## 改动`, `## 范围`, `## 取舍`, `## 影响面`, `## 验证`. Full SHAs, swarm or arena lane recitals, and long tables go in a linked artifact, not the body.

Resolve the forge once: `gh` by default, or `origin pr` when `command -v origin` succeeds and Origin can resolve the repository, with any fallback to `gh` recorded and never Graphite (`gt`). Stack follow-ups by base branch, so a child PR targets its parent's branch and moves onto trunk per `playbooks/shipping.md` step 4 as the parent merges. Open every PR ready, never as a draft, unless the user or the repository's PR rules ask for one. Use the host's built-in PR tool with `draft: false` when it has one, because a CLI-made PR misses what the tool tracks. Otherwise use `gh pr create` without `--draft`, or `origin pr create --status open`, and read the created PR back before reporting its status. Opening a PR does not start a babysit, except for an Autopilot-full or Autopilot-stack owner, whose brief assigns the babysit loop after its code-ready report.
