## pstack 流程与发现

本次按 Feature 的 `how`、`architect` 设计比较、实施、验证、独立审查执行。设计比较使用继承主会话模型的独立候选及 `xagent:claude` 候选，再由单独 Claude 交叉评判。主会话负责实现和最终复验。角色配置读取一次，没有修改共享策略或已安装插件缓存。

选择共用 `scripts/check.sh` 和只读的 `build-runtime.py --check`。运行时覆盖 Linux 最低版本与 macOS 当前语言运行时，构建在 Ubuntu 单独检查。真实厂商与双主控 E2E 保留独立验收。

实测发现旧构建器把本机目录和随机临时目录写进 bundle。新增四项回归在旧实现上全部失败，修复后通过。构建现在复制 Commander，并在临时源码目录运行 Bun，重复构建及更换工作目录后产物一致。旧分发产物已在本次改动中重新生成。

第一轮复审提出三点。复核后补上了执行权限丢失检测，并让构建与源码指纹使用同一份排除日志、Finder 文件和 TypeScript 缓存后的输入。这两项新增反例在修复前均失败、修复后通过。要求增加第二个 macOS build 任务的意见被撤回，因为 Ubuntu 上的产物比较已能发现与 macOS 生成产物的差异。官方 runner 清单显示 macOS 14 已弃用，因此配置改用 macOS 15。

注释审查删除了一条冗余测试说明，保留 argparse 使用的公开 CLI 说明、action 版本映射和 Bun 生成的注释。
